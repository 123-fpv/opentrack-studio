# 验证记录

版本：0.1.4。更新：2026-10-27。Windows x64，MSVC 2022，Qt 6.8.3，Release 构建。

## 0.1.4 新增验证

- 全新 MSVC Release 构建的 **11 项 CTest 全部通过**：工程、颜色、几何、路线、本地识别、原生赛道、AI 请求解析、图片拖入、2D、3D 和应用流程。最后的界面提示修改后再次通过应用流程和原生编解码检查。
- 实体与步骤分离：重复穿越引用同一实体；删除最后一步后保留明确的空路线。可选步骤及起飞点字段兼容原 v1 工程，非法引用、面、窗口、重复 ID 和非有限数值会被拒绝，失败不覆盖当前工程或文件。
- 面与方向：验证立方结构六面的窗口位置、三维法向及开口基向量；改变通过方向不旋转实体。引导点随实体平移、旋转和尺寸更新，独立引导点采用世界坐标。
- 人工动作：日字门下→上和上→下、三连门两个方向的交替穿越、单层及双层重力门俯冲和爬升，均保留明确的面交叉。名义尺寸下逐段检查与实际杆件包围盒的交点，相关模板没有穿杆或低于地面的路径；这不等于任意编辑后的碰撞规划。
- 独立起飞点：本地工程保留起飞架基点、朝向及原生扩展数据，不加入过门编号，也不生成降落记录。原生适配器已核对起飞架和三维检查窗口的坐标约定，重复穿越只增加检查窗口，不重复实体杆件；详见 [格式说明](format.md)。
- 3D：实际步骤窗口、数字标记点击、独立选中高亮、方向箭头、引导点和起飞放置回调有回归检查。密集编号避让后，同一窗口的八次穿越仍可分别点击；悬停查看实体关联。即使旧工程开启参考图，3D 输出也与无参考图一致，地面不显示来源图片。
- 本地路线识别：一张非公开设计图在原尺寸、75% 和 150% 缩放下均得到 16 个实体、24 次穿越及 5 个引导点，并单独设置起飞点。公开的合成图测试覆盖反向联门、日字门先上/先下、重力门爬升/俯冲和局部证据不补齐隐藏窗口。深度与面阶段仍属估计，一处正视日字投影明确标记为歧义；这些数量不证明所有动作已被正确还原。

自动界面测试使用 `offscreen` 软件透视回退；最终程序另通过原生 Windows OpenGL 应用流程，覆盖小框、俯视图和 3D 三个拖入入口、步骤编辑、独立起飞点、比例调整及撤销。README 截图来自最终程序的原创示例工程，不包含测试用户的设计图。这些结果不代表跨显卡兼容性或帧率基准。

## DeepSeek 官方接口实测

官方模型列表返回 `deepseek-flash` / DeepSeek-V4.1-Flash，输入类型为 `text`、`image`。

默认勾选“快速生成”，请求使用 `thinking.type = disabled`；取消勾选时启用思考模式。该参数依据 [DeepSeek 官方 Thinking Mode 文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

一次快速模式有效响应约用 4.455 秒，但只生成 15 组对象，并漏掉部分组合结构；此前也出现过无效 JSON 响应。无效数据不能作为有效草稿应用。此记录验证接口流程及失败边界，不证明识别准确率或固定响应时间。

选图或打开 AI 窗口不会发送图片，只有明确点击“生成草稿”才会发送缩放后的选定图片。密钥可由本机 Windows 凭据管理器保存，源码、工程及发布包均不包含用户密钥。
