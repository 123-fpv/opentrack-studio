# 使用说明

OpenTrack Studio 不需要应用账号注册或登录，工程保存在本机。蓝色门架俯视图识别在本地运行；实拍/航拍 AI 生成是可选的联网功能。首次打开默认显示可编辑的 3D 示例赛道。可旋转视角查看门架，也可通过场景上方的“俯视图”按钮切换到平面编辑。

## 从赛道图片生成草稿

1. 准备清晰的俯视赛道设计图。当前识别器面向蓝色门架符号；尽量裁掉视频字幕、工具栏、头像、组件库和四周装饰。
2. 导入图片，程序读取完成后会自动开始识别。
3. 等待识别结果生成门架草稿。识别在本机运行，不会把图片发往外部服务；生成结果可以撤销。
4. 检查漏检、重复识别和误检，补充或删除门架。
5. 校准比例，逐个核对门型、朝向、中心高度及通过顺序。
6. 保存 `.otproj` 工程，再导出 `.trk`。

照片、透视图、蓝色路线与门架混在一起的图，以及包含整套软件界面的截图，可能无法可靠识别。若检测不到门架，可继续把图片当作底图，手动放置门架。输入图本身没有提供的信息需要补充，自动生成的初始顺序只是草稿。

已有底图时，可点击“识别图片并生成赛道”重新生成；若当前已有门架，程序会先确认是否替换。比例、底图透明度和显示开关位于默认收起的“比例与底图设置”中，需要时再展开。

## 用实拍或航拍照片生成 AI 草稿

1. 点击左侧“实拍/航拍 · AI生成”，选择最多 8 张 JPG 或 PNG 照片。缩略图列表用于核对本次选择。
2. 填写已知门架宽度，默认值为 2.4 米；按实物尺寸修改。尽量提供能相互对应的重叠视角，并避免只拍到局部门架。
3. 在说明中补充起点、飞行方向、通过顺序和重复通过同一门等信息。照片没有提供的高度和顺序不能可靠自动恢复。
4. 输入自己的 DeepSeek API 密钥；已保存的密钥由 Windows 凭据管理器提供。勾选保存选项后可在本机凭据管理器中保留密钥，密钥不写入赛道工程。
5. 可先“测试连接”。明确点击“生成草稿”后，程序才会将缩放后的选定照片发送到固定的 DeepSeek 官方 API `https://api.deepseek.com`，使用 `deepseek-flash` 模型；生成期间可以取消。
6. 查看生成草稿的预览。确认使用后才会应用到工程；应用后仍可撤销、继续修改。

此功能依赖用户自己的 API 账户和联网服务。它生成供编辑的布局草稿，不是测绘或摄影测量重建；遮挡、透视、重复门架和缺少参照尺寸都可能使结果偏离现场。应用前请检查位置、比例、中心高度、朝向和通过顺序。

普通的蓝色门架图识别不调用 AI API，也不上传图片。实拍功能的图片发送由“生成草稿”按钮触发，不会因为选图或打开对话框自动上传。

## 比例与高度

画布坐标和门架尺寸使用米。图片比例是每像素对应的米数；可用已知长度估算：

```text
米/像素 = 图上某段的实际长度（米） ÷ 该段在图片中的像素长度
```

例如，图上 200 像素对应实际 10 米，比例为 `0.05 米/像素`。自动估计比例以典型门架大小为参考，需按真实设计校准。

门架“高度/中心高度”参数表示门架中心离场景原点平面的高度，不是门脚离地高度。一个高 2.4 米、贴地放置的标准门，其中心高度通常为 1.2 米；场景地形高低仍需在模拟器内确认。门架自身的“尺寸高度”与中心高度是两个不同参数。

朝向以度为单位：`0°` 指向平面坐标的 `+Z` 方向，`90°` 指向 `+X`。导入图片通常无法确定门架的正反面，导出前应校对通过方向。

## 编辑与路线

默认 3D 场景使用 OpenGL 绘制。拖动空白区域或按住鼠标右键拖动可旋转视角，中键或空格加拖动可平移，滚轮缩放。在右侧组件库选择门架后，点击场景放置。移动已有门架时，先点击选中，看到选中光圈后，再拖动已选中的门架移动。

门架属性仅在选中门架时显示，可修改位置、尺寸、中心高度和朝向。底部列表表示门架的通过顺序，应该按照实际飞行顺序检查。需要平面定位时，可切换到“俯视图”；“3D 视角”按钮可返回空间视图。

平滑路线连接门架中心，用于观察布局。它不是经过飞行动力学验证的最优飞行轨迹；显示的长度是平面几何路径长度，不代表实际飞行距离或圈速。交叉路段、同一个门多次通过和复杂组合，应特别核对顺序。

| 操作 | 快捷方式 |
| --- | --- |
| 打开工程或原生赛道 | `Ctrl+O` |
| 保存 / 另存 | `Ctrl+S` / `Ctrl+Shift+S` |
| 导入图片 | `Ctrl+I` |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z` |
| 复制选中门架 | `Ctrl+D` |
| 删除选中门架 | `Delete` |
| 适应画布 | `F` |
| 朝向每次减 / 加 15° | `Q` / `E` |
| 返回选择工具 | `Escape` |
| 缩放当前视图 | 鼠标滚轮 |
| 平移画布 | 鼠标中键拖动，或按住空格拖动 |
| 旋转 3D 视角 | 在空白区域拖动，或鼠标右键拖动 |

拖动门架可移动它。输入框获得焦点时，优先使用输入框自身的编辑操作。

## 保存工程

`.otproj` 是 UTF-8 JSON 格式的本地工程，包含门架、门序、尺寸、视图设置，以及嵌入的 PNG 底图。移动工程文件时无需另外携带原图。

保存采用先写临时文件、成功后提交的方式；格式校验失败时不会用无效内容覆盖已保存的工程。工程仍可能因磁盘问题、误操作或外部软件修改受损，建议按阶段另存版本。

## 导出到 VelociDrone

当前新建原生导出支持标准门、起终点门和绕旗。其他组合门架在没有确认原生对象映射前，导出会给出提示；编辑器不会把它们静默替换成另一种对象。

标准门的尺寸换算暂以 2.4 米为名义开口宽高，仍需在模拟器内校准。绕旗使用原生对象的默认尺寸，画布中的宽高参数不会改变其原生尺寸。读取已有 `.trk` 后，支持保留原始对象及扩展数据，但编辑器的绘制并不保证覆盖所有原生物件外观。

1. 选择与设计匹配的场景；演示工程使用 Football Stadium。
2. 导出一个 `.trk` 文件，保留 `.otproj` 作为可编辑原稿。
3. 将 `.trk` 放到 Windows 的“文档”目录。
4. 打开 VelociDrone 的 Track Editor，在 Import Track 中找到并导入该文件。
5. 核对场景原点、门架尺寸、朝向、位置、通过顺序和地面高度，再试飞。

导入路径依据 [VelociDrone 官方手册](https://www.velocidrone.com/desktop_manual)。本版本尚未完成安装版模拟器的实际导入和飞行验收；如模拟器拒绝文件，请保留原始工程、导出文件和错误提示，并记录模拟器版本。完整兼容说明见 [格式说明](format.md)。

## 构建运行

使用 Qt 6.8.3 MSVC 2022 x64 和 Visual Studio 2022 C++ 工具链，在仓库根目录执行：

```powershell
cmake -S . -B build -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/msvc2022_64"
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

构建完成后运行 `build/Release/OpenTrackStudio.exe`。若构建机未将 Qt 的 `bin` 目录加入 `PATH`，可先在 Qt 命令行环境启动，或按下面的方式部署依赖。

需要分发给未安装 Qt 的电脑时，用同版本的 `windeployqt` 收集动态库和插件，并随包附带 [第三方许可说明](../THIRD_PARTY_NOTICES.md)。项目当前的原生赛道加解密依赖 Windows BCrypt，跨平台支持需要另行实现。

项目的打包脚本会完成动态库、指定插件、可再分发运行库、文档和示例的收集，并保留 Qt 许可与第三方声明：

```powershell
./scripts/package.ps1 -QtDir "C:/Qt/6.8.3/msvc2022_64" -BuildDir build -OutputDir dist/OpenTrackStudio-Windows
```

输出目录必须不存在或为空，脚本不会删除已有包。首次打包会下载官方 QtBase 6.8.3 源码归档并校验 SHA-256，用于收集原始许可和声明；源码缓存在构建目录，完整源码不会被复制进运行包。应用运行不依赖这一下载步骤。

测试中的 `offscreen` 平台用于验证文件、识别和基础界面，不创建真实 3D OpenGL 视口，因此不能代表显卡渲染、交互帧率或模拟器试飞验收。
