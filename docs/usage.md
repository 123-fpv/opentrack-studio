# 使用说明

OpenTrack Studio 0.1.7 不需要应用账号注册或登录，工程保存在本机。设计图识别在本地运行；实拍/航拍 AI 草稿是可选联网功能。连续绕杆按入口、出口和遮挡关系表达，可在绕立柱的同时升降到另一开口，不先回原窗口再换层。默认 3D 使用浅灰实体地面；对照原图时，切换俯视图并打开 2D 参考图。

## 从赛道图片生成草稿

1. 准备清晰的俯视赛道设计图。深蓝色障碍轮廓配洋红色路线的图可识别组合结构；普通蓝色门架图使用基础检测。尽量裁掉视频字幕、工具栏、头像和组件库。
2. 将单张 PNG / JPG / BMP 拖到左侧“拖入赛道图片”小框、3D 场景或俯视图；也可点击小框或按 `Ctrl+I` 选图。读取后自动在本地生成。
3. 等待草稿出现。选中有路线证据的组件时，动作面板默认是“当前识别路线 · 连续绕杆”，直接显示当前步骤的 3D 动作；不必先套用手动整圈模板。按一次 `Ctrl+Z` 可恢复导入前的底图和门架。
4. 检查漏检、重复识别和误检，补充或删除门架。
5. 校准比例，分别核对实体结构与每次过门的窗口、面和方向；同一座门可能被多次穿越。
6. 设置独立起飞点，保存 `.otproj` 工程，再导出 `.trk`。

深色轮廓模式会分析单门、双联、三联、叠门和立方组合，并参考洋红路线及箭头排列门序；图例和文字不计作障碍，可辨认的起飞平台单独记录。其他配色、照片、透视图和完整软件截图可能无法可靠识别；简单蓝色模式尤其不能保证复杂组合和交叉路线的顺序。若检测不到门架，可继续把图片当作底图，手动放置，或点击“AI 解析当前图”打开联网草稿窗口。

同一窗口被路线多次访问时，可以生成引用同一实体的多个步骤。未经过或被遮住的窗口不会仅凭门型自动补全；路线中断、遮挡及立体面的解释仍需人工复核。实际距离、高度和飞行动作不能仅由符号外形确定。

识别会结合路线箭头、可见线段和杆件遮挡，推断连续进出、绕行侧、升降与深度。有足够遮挡证据的正视图也能生成推进路线；不会只因门型补一个闭环整圈。线索不足、路线断裂或前后关系无法区分时会提示待校对。证据不充分的高度与动作仍须按现场要求修正。

连续导入时，以最后一次导入为准。读取和识别在后台进行；若期间修改了工程，过期结果会被丢弃，避免覆盖新编辑。直接导入一张新图会生成替换草稿，可一次撤销；不会额外要求确认。

已有参考图时，可点击“识别图片并生成赛道”重新生成；若当前已有门架，程序会先确认是否替换。比例、透明度和 2D 参考图显示开关位于默认收起的设置中。工程仍保留原图，3D 完成场景始终使用实体地面。

## 用实拍或航拍照片生成 AI 草稿

1. 点击左侧“AI 解析当前图 / 多张照片”，选择最多 8 张 JPG 或 PNG 照片；一次拖入多张图片也会进入该窗口。缩略图列表用于核对本次选择，打开窗口不会上传图片。
2. 填写已知门架的横向中心距，默认值为 3 米；按实物尺寸修改。尽量提供能相互对应的重叠视角，并避免只拍到局部门架。
3. 在说明中补充起点、飞行方向、通过顺序和重复通过同一门等信息。照片没有提供的高度和顺序不能可靠自动恢复。
4. 输入自己的 DeepSeek API 密钥；已保存的密钥由 Windows 凭据管理器提供。勾选保存选项后可在本机凭据管理器中保留密钥，密钥不写入赛道工程。
5. 默认勾选“快速生成（优先速度）”。复杂组合可取消勾选后重试，两种模式都需要校对。可先“测试连接”；明确点击“生成草稿”后，程序才会将缩放后的选定照片发送到固定的 DeepSeek 官方 API `https://api.deepseek.com`，使用 `deepseek-flash` 模型；生成期间可以取消。
6. 查看生成草稿的预览。确认使用后才会应用到工程；应用后仍可撤销、继续修改。

此功能依赖用户自己的 API 账户和联网服务，响应时间没有固定保证。它可能漏掉障碍物、误判组合结构或返回无效数据；无效结果不会作为完整草稿应用。它不是测绘或摄影测量重建，应用前请检查位置、比例、中心高度、朝向和通过顺序。

本地深色轮廓和蓝色门架图识别都不调用 AI API。可选 AI 功能的图片发送由“生成草稿”按钮触发，不会因为拖图、选图或打开对话框自动上传。

## 比例与高度

编辑器使用 **X / Y 地面平面、Z 轴向上** 的显示方式。位置 X、位置 Y 控制地面上的位置；“Z 中心高度”控制组件中心离地的高度。右下角的 3D 坐标指示器中，竖直向上的轴标为 Z；俯视图显示 X / Y 平面。

画布坐标和门架尺寸使用米。图片比例是每像素对应的米数；可用已知长度估算：

```text
米/像素 = 图上某段的实际长度（米） ÷ 该段在图片中的像素长度
```

例如，图上 200 像素对应实际 10 米，比例为 `0.05 米/像素`。自动估计比例以典型门架大小为参考，需按真实设计校准。

新建标准门按杆件中心距计量：横、竖均为 3 米，每根方杆长 3.2 米、截面 0.1 × 0.1 米，净开口为 2.9 × 2.9 米，包含交叉重叠和杆端伸出部分。转向柱默认同样采用 0.1 × 0.1 米截面、长 3.2 米。属性中分别显示中心距、杆长、截面和净开口；导入旧工程时保留原来的尺寸约定。

“中心高度”表示组件中心离场景原点平面的高度，不是门脚离地高度。上述标准门和转向柱贴地放置时，中心高度均为 1.6 米；场景地形高低仍需在模拟器内确认。竖向中心距与中心高度是两个不同参数。

朝向以度为单位：`0°` 指向编辑器地面平面的 `+Y`，`90°` 指向 `+X`。缺少路线和遮挡证据时，图片无法可靠区分正反面，导出前应核对通过方向。

已有工程和模拟器文件的坐标保持兼容：程序内部及 VelociDrone 沿用 Y 轴向上的约定，编辑器显示时将内部 X / Z 平面显示为 X / Y，并将内部高度 Y 显示为 Z。打开旧工程或导出赛道不会因为坐标标签调整而旋转、交换或移动已有组件。

## 组合门与通过格

右侧“组合门 · 展开”显示五类组合。宽、高仍表示**每一格**的横、竖中心距，不是整个组合的宽高；默认每格 3 × 3 米，每根杆长 3.2 米、截面 0.1 × 0.1 米。

| 组件卡片 | 结构 | 默认整体宽 × 高 × 深 |
| --- | --- | --- |
| 双连门（双联门） | 并排两格 | 6.2 × 3.2 × 0.1 m |
| 三连门（三联门） | 并排三格 | 9.2 × 3.2 × 0.1 m |
| 日字门（叠门） | 上下两格 | 3.2 × 6.2 × 0.1 m |
| 单层重力门（立方门） | 四面立方框 | 3.2 × 3.2 × 3.2 m |
| 双层重力门（双层立方门） | 上下两个立方框 | 3.2 × 6.2 × 3.2 m |

位置和 Z 中心高度描述整个组合的中心。贴地的日字门和双层重力门中心高度为 3.1 米，其余上述组合为 1.6 米。先选中一次过门步骤，再用左侧“通过格”的列、层选择开口；列从组件本地左侧开始，层从下往上。修改通过格不会移动实体杆件。

## 实体组件与过门步骤

底部两个标签页分别管理场景物件和飞行顺序：

- **实体组件**中的 G1、G2 等是实际门架。移动、旋转和改尺寸会影响这个实体及其关联的所有穿越、引导点。
- **过门步骤**中的 1、2、3 等是每一次穿越。同一实体可出现多次，每次使用不同的格、面或方向；“重复本次”增加穿越记录，不复制杆件。“＋ 穿越”可把选中的实体加入顺序，“删本次”只移除这次穿越。
- **普通引导点**显示为小菱形，用于描述绕杆、爬升等路径；不占过门编号，只保存在工程中。
- **T 辅助翻绕检查点**是明确标记的关键外侧控制点，显示为 T1、T2 等。推进动作只保留必要的控制点，不把所有拟合采样点变成关卡。T 点按路线顺序导出，不复制实体，也不计作实际穿门次数。

点击底部步骤或 3D 中的数字标记，选中的开口会高亮，箭头显示实际穿越方向。悬停数字可查看所属实体和穿越次数，底部步骤也保留实体关联。航线显示时只显示选中实体的 G 编号，密集的过门数字会自动错开并用引线指向窗口。用“前移”“后移”调整过门顺序；实体数量与过门次数可以不同。

新增或复制实体会附带一次默认穿越，不会复制原实体的整套动作。选择过门步骤时，`Ctrl+D` / `Delete` 复制或删除本次穿越；选择实体时则复制或删除实体，删除实体也会移除引用它的步骤。修改图片比例时，实体位置、起飞点及独立引导点的地面位置会一起调整。

每次穿越可设置前面或背面；立方结构还能选择左面、右面、顶面、底面。面名以实体自身朝向为准。默认方向指向所选格内部；“反转穿越方向”翻转本次箭头，实体朝向保持原值。例如，顶面默认向下穿入，反转后向上穿出。

从立方框顶面进入、向左面出去时，应核对顶部向下和左面向外的两次穿越；左面出口需要反转其默认向内方向。双层立方框还需核对顶部、层间开口、下层出口的顺序。不要旋转整个立方框、用另一个正面冒充图中的左侧出口。

识别的孔内偏移和斜向飞行切线用于预览过门点，不移动原生门框完整窗口。工程保存这些路径信息；原生 `.trk` 保存的是完整窗口及明确的 T 控制点，不包含所有拟合轨迹。详细字段和方向校验见 [格式说明](format.md)。

## 手动校正动作

优先检查“当前识别路线 · 连续绕杆”的 3D 编号与进出箭头。此项只预览已有步骤，“应用动作”不会改写它。需要人工改动作时，再选择其他模板并点击“应用动作”：

| 选项 | 生成的动作 |
| --- | --- |
| 绕左立柱上升 / 下降 | 绕左侧立柱的同时换层，下层进上层出或上层进下层出；不返回旧窗口 |
| 绕右立柱上升 / 下降 | 沿右侧立柱连续换层；两次实际穿门之间有一个关键外侧 T 点 |
| 下门 → 绕中横杆 → 上门 / 上门 → 绕中横杆 → 下门 | 日字门两个窗口依次穿越，以弧线半绕共享横杆 |
| 左窗 → 右窗 / 右窗 → 左窗，交替穿越 | 双连或三连门按列交替正反穿越，以弧线绕过共享竖杆 |
| 重力门 · 圆弧俯冲穿出 | 从顶面向下进入，以圆弧从下部穿出 |
| 重力门 · 圆弧爬升穿顶 | 从下部进入，以圆弧向上穿过顶部；双层结构逐层通过 |
| 高级：绕中横杆或顶横杆独立整圈 ↻ / ↺ | 单独的闭环动作，回到原窗口；不替代图中的连续推进 |

绕立柱上升/下降使用沿立柱持续变化的高度，结束在另一层开口。三连、双连的识别路线还可保留高度与前后深度变化；手动联门模板是基础动作，不能替代已有的精细拟合轨迹。

高级闭环整圈的顺逆方向以从门左侧沿横杆看向右侧（组件本地 +X）、竖直朝上的侧视图为准，与当前相机位置无关。先看 3D 动作箭头，再决定是否应用；闭环整圈、半绕横杆和绕立柱推进是不同动作。

完整绕圈回到同一开口时，T 辅助检查点用于约束中间的绕行顺序，避免仅靠重合开口的两次记录表达一圈。导出后应按箭头依次经过 T 点；不要把它们删成普通预览引导点。原生触发范围及实际完成判定仍需模拟器试飞确认。

先打开公开合成示例 [threading-demo.otproj](../examples/threading-demo.otproj) 查看连续升降；[circle-demo.otproj](../examples/circle-demo.otproj) 仅用于高级闭环整圈。这些示例没有附带用户原图。

![绕立柱并连续换层的 3D 动作](threading-preview.png)

“应用动作”会替换该实体已有的全部过门动作和关联引导点，可用 `Ctrl+Z` 恢复。模板用于明确的人工校正；门型本身不能决定飞行动作，最终顺序应以设计图的路线、箭头或现场要求为准。应用后仍可逐次修改列、层、面和方向。

路线使用受约束曲线，保留每次过门点及飞行方向，检查与模型杆件、地面的 **0.20 m 预览净空**。穿越窗口本身保持完整，曲线可在孔内偏移、斜向通过。无法平滑连接时提示局部切向不连续；无法安全连接会断开显示，要求调整高度或引导点。

这不是动力学、真实地形碰撞或比赛规则判定。出现警告时应先修正工程；即使没有警告，也仍需试飞。旧工程没有独立步骤时继续按原门序预览，第一次编辑步骤后保存为显式顺序。

## 独立起飞点

若识别已生成起飞点，先核对其位置和方向；需要设置或重放时，点击“设置起飞点”或左侧“在场景放置起飞点”，再单击地面放置 `T/O` 标记。展开“坐标与朝向”，调整 X / Y 地面位置、“基点 Z”和朝向。基点 Z 对应原生起飞架的参考原点，无人机实际起飞位由模拟器的起飞架决定；它与门框的中心高度分别设置。

导出前必须设置独立起飞点。它不占用过门编号，也不把首个门当作起飞坐标；默认不创建降落点或落地动作。重新放置可调整平面位置，坐标和方向修改可以撤销。

## 编辑与路线

默认 3D 场景使用 OpenGL 绘制。拖动空白区域或按住鼠标右键拖动可旋转视角，中键或空格加拖动可平移，滚轮缩放。在右侧组件库选择门架后，点击场景放置。移动已有门架时，先点击选中，看到选中光圈后，再拖动已选中的门架移动。

门架属性仅在选中门架时显示，可修改位置、尺寸、中心高度、朝向和颜色。颜色可选 13 种原生方块色，也可点击“调色”选择任意 RGB；新建方块门和柱导出时会匹配最近的原生颜色。导入的旧模型仍保留原材质，编辑预览颜色不会更改它的原生贴图。需要平面定位时，可切换到“俯视图”；“3D 视角”按钮可返回空间视图。

显式路线的长度按三维路径计算，包含垂直穿越；旧式门序预览保留原来的平面长度约定。两者都只用于几何检查，不代表实际飞行距离或圈速。细柱较难选中时，可点击上方 G 编号或使用选中光圈。

| 操作 | 快捷方式 |
| --- | --- |
| 打开工程或原生赛道 | `Ctrl+O` |
| 保存 / 另存 | `Ctrl+S` / `Ctrl+Shift+S` |
| 导入图片 | `Ctrl+I` |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z` |
| 复制当前实体或过门步骤 | `Ctrl+D` |
| 删除当前实体或过门步骤 | `Delete` |
| 适应画布 | `F` |
| 朝向每次减 / 加 15° | `Q` / `E` |
| 返回选择工具 | `Escape` |
| 缩放当前视图 | 鼠标滚轮 |
| 平移画布 | 鼠标中键拖动，或按住空格拖动 |
| 旋转 3D 视角 | 在空白区域拖动，或鼠标右键拖动 |

拖动门架可移动它。输入框获得焦点时，优先使用输入框自身的编辑操作。

## 保存工程

`.otproj` 是 UTF-8 JSON 本地工程，包含实体、有序穿越、普通引导点、关键 T 点、孔内偏移与飞行切线、独立起飞点、视图和嵌入参考图。旧 v1 工程仍能打开；移动文件无需另带原图。继续修改识别路线时，优先打开工程，不以 `.trk` 代替可编辑原稿。

原生文件没有完整的组件归属与曲线信息，单独导入的 T 点可能成为独立世界坐标检查点。重新套用某个实体的动作时，程序不能凭空判断哪些独立 T 点属于旧动作；应检查并移除不再需要的独立点，或返回原 `.otproj` 修改。

保存采用先写临时文件、成功后提交的方式；格式校验失败时不会用无效内容覆盖已保存的工程。工程仍可能因磁盘问题、误操作或外部软件修改受损，建议按阶段另存版本。

## 导出到 VelociDrone

当前新建原生导出支持方梁标准门、起终点门、转向柱，以及上述五类带新结构尺寸约定的组合门。未支持的类型及没有相应结构标记的旧组合会给出提示，不会静默替换为另一种对象。

每个实体只输出一份杆件；每次实际穿门输出对应完整窗口与接受方向的顺序检查点。明确的关键 T 点按同一顺序输出为原生不可见检查点 88；普通拟合引导点不导出。孔内偏移及斜向飞行切线不移动、缩小或倾斜原生实体窗口。独立起飞点另输出起飞架。旧原生模型未校准的重复穿越/任意面会提示转换，详见 [格式说明](format.md)。

原生检查点按模拟器本地 **−X** 接受方向写入，编辑器箭头表示应飞过窗口的方向。0.1.4 工程应核对后重新导出。旧工程误用的闭环动作不会静默改成推进；请从原图重新生成，或明确选择推进模板，再另存工程和导出。

1. 选择与设计匹配的场景，设置起飞点，逐次核对过门步骤；演示工程使用 Football Stadium。
2. 导出一个 `.trk` 文件，保留 `.otproj` 作为可编辑原稿。
3. 将 `.trk` 放到 Windows 的“文档”目录。
4. 打开 VelociDrone 的 Track Editor，在 Import Track 中找到并导入该文件。
5. 核对场景原点、门架尺寸、朝向、位置、通过顺序和地面高度，再试飞。

导入路径依据 [VelociDrone 官方手册](https://www.velocidrone.com/desktop_manual)。此前测试文件已通过安装版模拟器导入、场景载入；0.1.6 推进路线另有独立原生数据和几何核对，但完整飞行、关键 T 触发、碰撞仍待实飞验收。发生问题时保留工程、导出文件、版本及错误信息，详见 [格式说明](format.md) 与 [验证记录](validation.md)。

## 构建运行

使用 Qt 6.8.3 MSVC 2022 x64 和 Visual Studio 2022 C++ 工具链，在仓库根目录执行：

```powershell
cmake -S . -B D:/CodexWork/OpenTrackStudio/build -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/msvc2022_64"
cmake --build D:/CodexWork/OpenTrackStudio/build --config Release
ctest --test-dir D:/CodexWork/OpenTrackStudio/build -C Release --output-on-failure
```

构建完成后运行 `D:/CodexWork/OpenTrackStudio/build/Release/OpenTrackStudio.exe`。没有 D 盘时改用其他数据盘目录；无需移动源码或已安装 Qt。若 Qt 的 `bin` 不在 `PATH`，可从 Qt 命令行环境启动，或部署依赖。

需要分发给未安装 Qt 的电脑时，用同版本的 `windeployqt` 收集动态库和插件，并随包附带 [第三方许可说明](../THIRD_PARTY_NOTICES.md)。项目当前的原生赛道加解密依赖 Windows BCrypt，跨平台支持需要另行实现。

项目的打包脚本会完成动态库、指定插件、可再分发运行库、文档和示例的收集，并保留 Qt 许可与第三方声明：

```powershell
./scripts/package.ps1 -QtDir "C:/Qt/6.8.3/msvc2022_64" -BuildDir D:/CodexWork/OpenTrackStudio/build -OutputDir D:/CodexOutputs/OpenTrackStudio-Windows
```

输出目录必须不存在或为空，脚本不会删除已有包。首次打包会下载官方 QtBase 6.8.3 源码归档并校验 SHA-256，用于收集原始许可和声明；源码缓存在构建目录，完整源码不会被复制进运行包。应用运行不依赖这一下载步骤。

测试中的 `offscreen` 平台用于验证文件、识别和基础界面，不创建真实 3D OpenGL 视口，因此不能代表显卡渲染、交互帧率或模拟器试飞验收。
